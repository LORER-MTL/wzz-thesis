\Chapter{Benchmark results}\label{sec:Theme2}

In this chapter we evaluate the engine of \S\ref{sec:Theme1} against CVXPY's existing
canonicalization paths. The central question is the cost of repeatedly forming the problem data for
a parameterized problem family, which is exactly the regime our two-phase design targets.

\section{Benchmark Setup}

\paragraph{Baselines.}
We compare three ways of forming the problem data:
\begin{itemize}
  \item the \textbf{DPP path} (CVXPY's default), which builds the parameter tensor once and applies
  it on each solve;
  \item the \textbf{\texttt{ignore\_dpp} path}, which re-canonicalizes from scratch on every solve
  and places no restriction on how parameters enter;
  \item \textbf{our C engine}, which fixes the sparsity pattern once and refills numerical values on
  each solve.
\end{itemize}

\paragraph{Metrics.}
For each method and problem we report the \emph{cold-start} time (the first solve, including any
one-time setup), the \emph{warm-restart} time (a subsequent solve with new parameter values
$\theta$), and the \emph{peak memory}. From the cold- and warm-restart times we also report the
\emph{break-even} point: the number of solves on the same problem family after which our engine's
cumulative time falls below that of the \texttt{ignore\_dpp} path. All experiments pin a single
CVXPY version and run on a fixed machine; full hardware and software details accompany the results.
