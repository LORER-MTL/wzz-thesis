\section{Current approach and its limitations}

The previous chapter described expression trees and how \texttt{CVXPY}
represents affine functions as compositions of linear operators. This section
examines how \texttt{CVXPY} currently evaluates those trees to produce
solver-ready coefficient matrices, and why that approach has limitations that
motivate the present work.

\paragraph{Sparse matrix multiplication}
\texttt{CVXPY}'s current approach is to convert the linear operator tree into
a single sparse matrix. The tree is traversed in post-order: each leaf node
returns its coefficient matrix, and each internal node composes its children's
matrices via sparse matrix multiplication. For example, in the expression
\texttt{sum(A @ x)}, the traversal first returns $A$ at the \texttt{matmul}
node, then multiplies by $\ones^T$ at the \texttt{sum} node, yielding
$\ones^T A$. The final matrix at the root is returned.

\paragraph{Limitations}
This approach requires storing intermediate sparse matrices at each node
during traversal. For deep expression trees or large problem dimensions, this
leads to significant memory overhead. Additionally, sparse matrix
multiplication is computationally expensive and may produce matrices with more
nonzeros than the operands, further increasing memory and runtime costs.

\paragraph{Motivation}
These limitations are particularly acute in embedded and real-time settings
where memory budgets are tight and latency requirements are strict. A method
that avoids forming intermediate matrices entirely---by directly manipulating
the sparse storage arrays---could achieve the same result with lower overhead.
The remainder of this chapter develops such a method.

\subsection{Direct encoding of linear operators}

Rather than composing operators via sparse matrix multiplication, we keep the
coefficient matrix in CSR (Compressed Sparse Row) format and directly
manipulate its index arrays without forming intermediate matrices. Each linear
operator is implemented as a transformation on the CSR arrays
\texttt{(indptr, indices, data)}. For example, the \texttt{sum} operator
collapses all rows into row~0 by setting all entries of \texttt{indptr} to
$[0, \texttt{nnz}]$, effectively mapping every row index to~0 without any
matrix multiplication.
